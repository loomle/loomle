# Loomle 0.7.16

Loomle 0.7.16 improves Blueprint sandbox safety for SAL preflight on Unreal
Engine 5.7 and 5.8. The Client-Bridge protocol remains version 6.

## Blueprint sandbox safety

- Sandbox names now avoid collisions with UE's derived generated and skeleton
  class names. This prevents native duplication from overwriting unrelated
  objects and triggering a UObject reference-count assertion.
- Preflight checks generated/skeleton class ownership and existing CDO validity
  and class identity before duplication. Unsafe state returns the existing
  diagnostic with compile and re-query guidance.
- Blueprints with native compiler errors remain editable. Dry run, live graph
  removal, and Undo are covered without bypassing UE duplication or compilation.
- Adds regressions for Widget object defaults, function signature changes,
  global/contextual byte-to-int actions, and unsupported foreign-variable actions
  across native compile and garbage collection.

## Verification and remaining coverage

Local Win64 native validation passes 207/207 tests on UE 5.8.1 and UE 5.7.4.
The class-name collision regression crashes on unchanged 0.7.15 and passes with
this repair. Release packages additionally pass the paired Mac and Windows
verification workflows before publication.

The original assets from [issue 201](https://github.com/loomle/loomle/issues/201)
and [issue 202](https://github.com/loomle/loomle/issues/202) were unavailable
locally. Their exact UE 5.8.3 crash state still requires verification in the
reporter's project; this release does not claim both reports are resolved.

Install one complete 0.7.16 package matching the installed Unreal Engine version
so the bundled Client and Bridge remain version-aligned.

## macOS security notice

The bundled agent-invoked Client and Bridge are not signed with a Loomle
Developer ID certificate or notarized by Apple. macOS Gatekeeper may therefore
require explicit approval before the Client can run.

## Windows security notice

The bundled agent-invoked Client and Bridge are not Authenticode-signed.
Windows may therefore show a trust or SmartScreen warning, and restrictive
Smart App Control policies may block execution until the files are approved.
