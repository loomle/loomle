# Loomle 0.7.11

Loomle 0.7.11 keeps the Unreal and SAL behavior of 0.7.10 while making each
distribution channel independently identifiable and updatable.

## Supported environment

- Unreal Engine 5.7 and 5.8
- macOS on Apple Silicon
- Windows on x64
- Engine-plugin installation

## Clear distribution channels

- Gives GitHub, Fab, MCP Registry, and Claude packages explicit channel
  identity without changing the bundled Client executable for each platform.
- Keeps update recommendations inside the package's originating channel, so a
  Fab installation follows Fab releases rather than the faster GitHub stream.
- Directs Codex users to the public GitHub distribution instead of presenting
  a separate Codex marketplace channel that users cannot discover.

## Agent packages and MCP Registry

- Produces MCP Registry and Claude Desktop packages from the same
  self-contained Loomle Client used by the Unreal plugin distributions.
- Publishes immutable agent-package candidates alongside the verified GitHub
  Release, while keeping store promotion as a separate reviewed step.
- Adds an MCP Registry promotion workflow that verifies the release tag,
  artifact digest, package version, and Registry response before accepting the
  publication.

## Fab packaging

- Keeps one cross-platform Fab source package containing the UE plugin source
  and both native companion Clients.
- Uses adjacent channel metadata to distinguish Fab from GitHub while retaining
  byte-identical Client executables for the same platform.
- Continues to omit Unreal build outputs from the Fab source package so Fab can
  compile the plugin independently for each supported engine version.

## Compatibility

SAL remains at version 3. The Client–Bridge protocol remains version 5; install
one complete 0.7.11 package so the bundled Client and Bridge remain
version-aligned. Choose the package matching the installed Unreal Engine
version.

## macOS security notice

The bundled agent-invoked Client and Bridge are not signed with a Loomle
Developer ID certificate or notarized by Apple. macOS Gatekeeper may therefore
require explicit approval before the Client can run.

## Windows security notice

The bundled agent-invoked Client and Bridge are not Authenticode-signed.
Windows may therefore show a trust or SmartScreen warning, and restrictive
Smart App Control policies may block execution until the files are approved.
