# Loomle 0.7.10

Loomle 0.7.10 hardens Unreal Python execution and fixes native identity for
component-bound Blueprint Graph Palette actions.

## Supported environment

- Unreal Engine 5.7 and 5.8
- macOS on Apple Silicon
- Windows on x64
- Engine-plugin installation

## Unreal Python reliability

- Admits Python work through a safe engine-tick path so scripts do not execute
  inside unsafe RPC or Slate callbacks.
- Keeps the Python fallback available during PIE while preserving explicit
  Editor-runtime ownership, polling, timeout, and runtime-loss behavior.
- Adds resident `use-unreal-python` guidance for capability discovery,
  idempotent mutation, continuation recovery, and verification.
- Adds focused `debug-unreal-pie-with-python` guidance for PIE lifecycle,
  Game World selection, cross-frame observation, and cleanup.

## Blueprint Graph Palette identity

- Gives component-bound function actions distinct Palette identities by adding
  their native Blueprint object-property identity to the Node spawner
  signature.
- Preserves SCS component identity through its stable `VariableGuid` rather
  than localized menu titles or menu order.
- Allows copied component actions such as `Set Relative Rotation
  (PreviewMesh)` to resolve uniquely from both object and struct Pin contexts.
- Keeps unresolved indistinguishable actions fail-closed with
  `resolution.palette_ambiguous`.

## Documentation and release engineering

- Documents the eighth public MCP call, its Python safety boundary, and the
  matching resident Skills.
- Updates public installation guidance for the engine-specific UE 5.7 and UE
  5.8 packages and the current Fab/GitHub release relationship.
- Repairs verified artifact download handling in the GitHub promotion path.

## Compatibility

SAL remains at version 3. The Client–Bridge protocol remains version 5; install
one complete 0.7.10 package so the bundled Client and Bridge remain
version-aligned. Choose the package matching the installed Unreal Engine
version.

## macOS security notice

The bundled agent-invoked Client and Bridge are not signed with a Loomle
Developer ID certificate or notarized by Apple. macOS Gatekeeper may therefore
require explicit approval before the Client can run.

## Windows security notice

The bundled agent-invoked Client and Bridge are not Authenticode-signed.
Windows may therefore show a trust or SmartScreen warning, and restrictive
Smart App Control policies may block execution until the files are approved.
