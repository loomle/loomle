# Loomle 0.7.7

Loomle 0.7.7 moves Client update discovery from a Loomle-hosted manifest to
GitHub's public latest-release metadata, making each promoted GitHub Release the
single continuing source for its version, download URL, and SHA-256 digest.

## Supported environment

- Unreal Engine 5.7
- macOS on Apple Silicon
- Windows on x64
- Engine-plugin installation

## GitHub-native update discovery

- Reads GitHub's public `releases/latest` API only when `status` checks for an
  update.
- Requires a published stable `v<version>` tag and the exact uploaded
  `loomle-bridge-<version>.zip` asset.
- Uses the asset URL and SHA-256 digest returned by the same GitHub Release,
  avoiding a separately maintained website version or checksum.
- Keeps offline access, malformed metadata, unsupported targets, rate limits,
  and timeouts informational so they cannot block project or SAL operations.
- Sends prerelease Clients directly to the latest stable release instead of
  maintaining a separate RC update channel.

## Legacy Client migration

The website manifest is published one final time for 0.7.7 and then frozen.
Clients through 0.7.6 can therefore discover and install 0.7.7; Clients from
0.7.7 onward discover every later stable version directly from GitHub.

## Compatibility

SAL remains at version 3 and the Client–Bridge protocol remains at version 4.
This maintenance release does not change the Client–Bridge compatibility
boundary. Install one complete 0.7.7 platform package so the bundled Client and
Bridge remain version-aligned.

This release remains supported on Unreal Engine 5.7 and does not declare Unreal
Engine 5.8 support.

## macOS security notice

The bundled agent-invoked Client and Bridge are not signed with a Loomle
Developer ID certificate or notarized by Apple. macOS Gatekeeper may therefore
require explicit approval before the Client can run.

## Windows security notice

The bundled agent-invoked Client and Bridge are not Authenticode-signed.
Windows may therefore show a trust or SmartScreen warning, and restrictive
Smart App Control policies may block execution until the files are approved.
