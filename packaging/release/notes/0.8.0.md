# Loomle 0.8.0

Loomle 0.8.0 gives agents one stable `editor` call for inspecting and
controlling Blueprint presentations. Agents can read the active Editor context,
open an exact Blueprint or Graph, and close that presentation without inventing
a UI model outside Unreal Engine.

## Supported environment

- Unreal Engine 5.7
- macOS on Apple Silicon
- Windows on x64
- Engine-plugin installation

## Unified Editor control

- Added `context`, `open`, and `close` operations to the public `editor` MCP
  call. Calling `editor({})` defaults to `context`, while `open` and `close`
  require one exact Target.
- Added Blueprint and Blueprint Graph presentation control through Unreal's
  native asset-editor, Blueprint-editor, document-tab, and focus paths.
- Made presentation operations idempotent, with explicit outcomes such as
  `opened`, `focused`, `already_focused`, `closed`, and `already_closed`
  instead of treating an already-satisfied state as an error.
- Verified the resulting native Editor state after each operation, including
  the owning Blueprint Editor, exact Graph document, foreground tabs, focus,
  and final tab detachment when closing.

## Canonical SAL Targets

- The `editor` call's `open` and `close` operations accept one bare canonical
  SAL Blueprint or Graph Target expression, using the same asset identity and
  Graph identity as SAL queries and patches.
- Added strict Target parsing, resolution, diagnostics, and result validation
  so unsupported, ambiguous, or unresolved presentations fail without opening
  or closing a different Editor surface.

## Public interface migration

- Removed the public `editor_context` MCP call. Agents and host integrations
  must use `editor({})` for the current context.
- Kept Editor context, presentation control, and their diagnostics under one
  public interface so agents do not need to discover separate tools for each
  window action.

## Documentation and website

- Updated the README, formal SAL documentation, agent guidance, interface
  catalog, examples, and website to document the unified `editor` call and the
  removal of `editor_context`.
- Added Blueprint and Graph Target examples together with operation outcomes,
  failure behavior, and migration guidance.

## Compatibility

SAL remains at version 3. Loomle 0.8.0 uses Client–Bridge protocol version 4,
while Loomle 0.7.3 uses protocol version 3. Do not mix a 0.7.3 Client or Bridge
with a 0.8.0 counterpart; install one complete 0.8.0 platform package so the
bundled Client and Bridge remain matched. Loomle rejects mixed protocol versions
instead of attempting an unsafe request.

This release remains supported on Unreal Engine 5.7 and does not declare Unreal
Engine 5.8 support.

## macOS security notice

The bundled agent-invoked Client and Bridge are not signed with a Loomle
Developer ID certificate or notarized by Apple. macOS Gatekeeper may therefore
require explicit approval before the Client can run.

## Windows security notice

The bundled agent-invoked Client and Bridge are not Authenticode-signed.
Windows may therefore show a trust or SmartScreen warning, and restrictive
Smart App Control policies may block execution until the files are approved.
